# RTL433 1.0 for T-Embed WirelessPi

Native ESP32-S3 external app for the Sor3nt-based WirelessPi firmware. Uses the T-Embed CC1101 receiver. No Raspberry Pi or SDR dongle is involved. This is not a stock Flipper Zero binary.

Implemented:
- OOK and 2-FSK pulse decoding through the vendored rtl_433_ESP decoder library.
- 377 catalog entries, including one non-runnable template; 333 entries enabled by the upstream defaults. Catalog presence does not guarantee a device can be received with the chosen CC1101 settings.
- Individual decoder switches, stored settings, seven receive profiles, editable frequency, RSSI threshold, optional frequency hopping.
- Compact text throughout, launcher icon, live decode counts, device history and full decoded JSON details.
- Latest 64 model/ID/channel groups, bounded to 1 MiB of JSON history. Group keys are not guaranteed physical device identities.
- JSONL session logging (5 MiB per session) and JSONL/CSV history export. CSV includes the complete JSON for heterogeneous sensor fields.
- Last raw pulse capture, transparent `.rtl` pulse files and offline decoding of those files.
- Queue-overflow counters and bounded capture/decoder queues. An overflowed pulse burst is discarded rather than presented as complete.

Install `rtl433.fap` in `apps/Sub-GHz/` on the SD card. Its imports resolve against the previous `2.0.0-pi11-wifite` release as well as Native Tools 1.0, so RTL433 itself does not require a new firmware flash.

Controls: turn to select/scroll, OK to open/toggle. BACK stops reception and returns to the menu. In details, hold OK to export history; in raw-pulse view, OK saves the capture. Frequency editing uses turn to change a character, OK to move, hold OK to save and BACK to cancel. All files are under `apps_data/rtl433/`.

The default is 433.92 MHz, alternating OOK 650 kHz and the native FSK profile, with a -90 dBm threshold. A known sensor generally needs its matching frequency and receive profile selected. Frequency hopping is off initially; it scans 315, 433.92, 868.35 and 915 MHz when enabled. Reception is passive.

## Scope and validation

This is a receiver/decoder adaptation, not every feature of desktop rtl_433. There is no SDR I/Q input/output, USB SDR driver, rtl_tcp server, MQTT publisher, Linux command line or radio transmission. FSK capture uses RSSI gating; short bursts and weak signals may be missed. Very long/high-rate frames may exceed the 1,200-pair capture or decoder limits. The CC1101 supports one frequency/profile at a time.

The native app compiles and its firmware imports resolve. Address/undefined-behavior sanitizer tests decoded a known Prologue OOK fixture and a published Ambient Weather WH31E FSK fixture, exercised the full default decoder set with noisy inputs, tested pulse parsing, and checked the compatibility math/calendar functions. These are host tests. Live RF reception, device memory headroom and cancellation under hardware load have not been verified on a physical T-Embed.

The bundled calendar compatibility is UTC, using the RTC snapshot plus monotonic elapsed time. The display's capture timestamps are uptime milliseconds. No real-time clock accuracy is implied.

Run host tests from the project root: `bash applications_user/rtl433/tests/run.sh`. Upstream source provenance and licenses are in `UPSTREAM.md`, `LICENSE` and the preserved source notices.
